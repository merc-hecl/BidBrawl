# 游戏与物品配置

物品模板可选 `translations`，按语言代码提供名称，例如 `"translations": {"en": "Cut-crystal decanter"}`。WebUI 图鉴按当前语言显示该字段；没有对应翻译时保留 `name`。内置物品的英文名同样存放于目录 JSON，不在界面代码中维护。

`-game-config` 加载尺寸、品质区间、权重、初始资金、门票与专长；默认配置见 internal/game/default.json，离线导出用 `bidbrawl config -defaults`。初始现金 600000，只影响新注册账号。五档价格为 80–320 / 300–1300 / 1000–5000 / 3000–15000 / 8000–50000，权重 45/30/15/8/2。

五档区间允许局部重叠：最高品质目标不必是最高价目标；同品质也会因具体身份和 value_percent 出现明显价差。尺寸与品质仍不强制正相关。扩大价格区间时保留史诗/传说区间中点，避免仅靠抬价加剧资金封顶；仓库建议现金同步为 600000，已有账号现金不重置。

固定种子 20261018/1、每仓型 400 个生成样本（只统计常规物品，非 Agent 对战）中，综合/数码/旧宅仓值中位数分别为 259265/275770/277280，95 分位为 539038/561796/583802；超过新号扣票后 595000 现金的比例为 2.25%/3%/4.5%。旧资金与价档下同一组抽样约四成超过现金。最高常规品质贡献约 27%～28%，并非价值来源的绝对多数。生成分布回归见 TestDefaultLotValueDistribution；这些样本不证明玩家策略已平衡。

物品目录独立存放于 internal/game/items.json，含 categories、warehouses、items。宿主 `-items-config PATH` 可替换物品模板列表（使用现有20个常规品类及彩蛋、五档常规品质和独立彩蛋档）；也可在 game-config 的 catalog 数组中配置模板。每档至少有一个常规 1×1 模板，确保任意剩余空间可填充。当前内置560个独立常规模板及8个彩蛋模板。字段为 id、name、category、quality、width、height、value_percent，可选 tags（如 clock）。后者是该档价格区间内 0–100 的位置，价格 = min_price + floor((max_price-min_price)×value_percent/100)。原始目录不使用市场价；实际价格由 catalog / state.rules.catalog 展示。无立绘依赖。

每件具体物品只有一个固定品质，名称以材料、用途、型号、工艺或来源区分，不给同一原型套五档通用品质前缀。品质是本游戏的价格档位，不是现实鉴定评级；附来源记录、签名或证书的名称属于游戏内设定。尺寸按收纳占格表达，卷轴、折叠件、成套物品按存放状态设计，不是实际长度比例。常见轮廓跨品质保留多种候选，类别与尺寸可以进一步缩小范围，独特组合允许直接定位；不再强制每个类别的每种尺寸都有五档版本。各档模板数量不决定品质出现率，仍先按配置权重抽品质，再选可放入的物品。

公开目录中的 `quality_appearance_probability` 对常规品质按五档常规权重单独计算，排除彩蛋，五档之和为1（默认45%、30%、15%、8%、2%）；彩蛋档单独返回其基础抽取概率，不参与常规品质归一化。`appearance_probability` 是该件具体物品的基础单次抽取概率，仍计入彩蛋占用的抽取机会，保持与实际抽取机制一致。两者均由后端计算（0–1），不是数据文件中的手填概率；完整候选池、空间足够时，单件概率按该档可放入模板分配，主题品类计三份权重。物品无法放入配置箱体时单件概率为0。过滤查询不会重新归一化；房间查询、状态与复盘使用房间冻结配置和仓库偏好。生成后续物品时，剩余空间会进一步筛选候选，因此该值不代表每个装箱位置的条件概率，也不代表整箱至少出现一次的概率。WebUI 仅把后端数值格式化为百分比。

生成时先选占用行数，按原 skyline 顺序找到可填位置，再按品质权重抽档、从可放入的该档模板中抽取。主题对应品类在候选池中权重三倍；其余品类仍可能出现。固定模板决定形状与价值，不再先生成任意矩形再贴物品名称。所有占用行完整覆盖、底部可留空。目录和规则随房间快照保存，重启不会重抽。

账号 assets 表示现金。买卡扣现金、卡入库；用卡与库存扣除在房间事务中提交。成交扣报价并发放藏品，系统回收才增加现金。归档、删除对局不删除拥有的物品或重算余额。卡耗按实际购入成本计入本局净收益，未使用库存不算本局成本。配置变化不重置旧账号。

保留当前格式，不提供过时对局快照兼容。当前对局快照版本 9、账号数据库元数据版本 3。开发测试环境清理过时对局时保留账号及 DPAPI 凭据。

物品结构参考 [竞拍盒子](https://bidking.site/data/items) 和 [即刻落槌档案馆](https://ddangcalc.com/zh/items)：同形多候选、分类缩小范围、小物品也可很贵。首版名称与价格为本项目扩展后的平衡数据，不是原作数据的完整移植。

彩蛋 category=easter_egg，quality=easter_egg，1×1，fixed_price=17500000；与普通价格区间分离。抽取时普通品质权重乘1000，彩蛋权重为传说原权重，故彩蛋概率严格为传说概率的千分之一，模板数量不改变总概率。默认彩蛋整体概率为2/100002（约每50001件一次），8个模板平均分配后单件概率为1/400008。`game_config.qualities` 只配置五档常规权重；`rules.qualities`、`/api/config` 与完整 `catalog` 返回的 `qualities` 另含独立彩蛋档。初始抽检、卡牌、专长与公共线索均排除彩蛋；数量、面积、均价和总价等侦察统计也不包含彩蛋。玩家在结算开箱后获知彩蛋，结算仍计入其完整价值；授权人类观察者的全箱视角保持完整。

26种专长定义在 internal/game/specialties.json，并随房间 game_config.specialties 冻结。steps 描述轮次、范围、数量、字段、均价/存在性及跨轮样本引用。可在 game-config 中覆盖 specialties；玩家用 catalog 查询。

ticket_fee 默认为5000，建房 ticket_fee 可覆盖（CLI -ticket），0为免费。成功开局时房间状态和全部门票在同一事务中提交；不足或持久化失败不扣票。退出用 POST /api/withdraw，拒绝报0；退出不退款、不收额外罚金。

私有行动存于房间 activities：请求只记录白名单参数、结果摘要、状态、时间和理由，不存凭据或完整原始请求。服务器事件与CLI上报来源分开；手册离线且匿名时无法记录。公开 state/replay/SSE 不携带私有行动、计数或修订号，个人 self.activities 和独立观察接口按权限读取，复盘帧在后端裁剪未来行动。

均价结果不附带范围总件数，避免直接等价于精确总值。家居专长已在第1轮给件数，因此第3轮采用最多3件抽样均价（sample_size=3），第5轮仍给完整总值；样本均价包含 sample_count/sample_limit 并明确标识。通过付费品质普查与均价组合推导总值属于预期的情报组合收益。

条件专长的 step.condition 可省略，或为 previous_unique_highest（上一轮唯一正最高价）、previous_below_highest（上一轮正报价严格低于最高价）。只读取前一轮公开 history；并列最高不触发这两个条件。第1轮禁止配置上一轮条件，提前成交后也没有下一轮奖励。弃权者不再获得专长信息。

领价追踪让早期争价承担被提前成交的风险；跟价研判从跟价获得统计和抽样信息，但不保证获箱或盈利。古器溯源沿同批样本分轮补属性，户外检验以极值目标、均面积与整类总价形成不同节奏。所有结果保存后复用，不在 state 查询或重连时重算。
