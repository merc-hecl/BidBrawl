# 游戏配置：尺寸、品质价格与资产

宿主通过同一份 JSON 配置箱体尺寸、物品尺寸、五档品质的价格与生成权重，以及新账号初始资产。配置启动时严格校验，不热更新；新房间保存独立快照，已有房间按保存的配置恢复。账号、资产和对局跨重启保留。

```powershell
bidbrawl config -defaults > game.json
bidbrawl host -game-config ./game.json
```

完整默认配置：

```json
{
  "schema_version": 2,
  "box": {"width": 20, "height": 30},
  "items": {"max_width": 4, "max_height": 4},
  "qualities": [
    {"id":"common","name":"普通","min_price":100,"max_price":300,"weight":45},
    {"id":"uncommon","name":"优良","min_price":1000,"max_price":3000,"weight":30},
    {"id":"rare","name":"稀有","min_price":10000,"max_price":30000,"weight":15},
    {"id":"epic","name":"史诗","min_price":100000,"max_price":300000,"weight":8},
    {"id":"legendary","name":"传说","min_price":1000000,"max_price":3000000,"weight":2}
  ],
  "initial_assets": 100000
}
```

| 字段 | 含义 | 默认值 |
|---|---|---|
| `box.width` / `box.height` | 箱体列数 / 行数 | 20 / 30 |
| `items.max_width` / `items.max_height` | 单件物品最多占用列数 / 行数 | 4 / 4 |
| `qualities[].id` | 固定品质 ID | 五档各一次 |
| `qualities[].name` | 品质名称 | 普通、优良、稀有、史诗、传说 |
| `qualities[].min_price` / `max_price` | 单件物品最低 / 最高金币价格 | 见上表配置 |
| `qualities[].weight` | 生成权重，总和必须为 100 | 45 / 30 / 15 / 8 / 2 |
| `initial_assets` | 新账号的一次性初始资产 | 100,000 金币 |

品质 ID 必须恰好包含 `common`、`uncommon`、`rare`、`epic`、`legendary`，不可重复或增加其他 ID。价格为整数，满足 `0 ≤ min_price ≤ max_price ≤ 1,000,000,000`；名称为非空且最多 32 字符。权重为 0～100 的整数，允许设为 0 停止生成某档物品。每件物品按权重独立抽取品质，再在该档价格区间内等概率抽取整数价格（含两端），价格不乘物品面积。技能结果、公共价格线索和结算均使用这次生成的实际价格。

初始资产为 1～1,000,000,000,000 的整数。注册时写入账号的 `assets` 字段，默认 100,000；修改配置不会重置已有账号。每次成交只更新获箱者：`assets += 箱内总价值 − 成交价`，其他玩家不变。账号资产直接持久化，与房间结算在同一事务中保存，不依赖历史成绩重算。报价范围为 **0～本人当前资产**，从本人 `state.self.assets` / `state.self.max_bid` 或 `me.assets` 查看。

同一账号同时只能加入一个未结算房间，包括等候中和已归档的等候房间；该房间结算或删除后可加入下一局。只有成交时支付一次该轮报价，每轮报价不累加扣款。重启、归档或删除已完成房间不改变账号资产，重复查询和重复请求不会重复结算。

尺寸均为正整数格子数。箱体最多 128 列或 128 行，总容量最多 4096 格；物品占格上限的行列数范围为 1～128。物品最小占格固定为 1×1 格，实际占格同时受箱体及剩余格子约束，物品上限大于箱体时也不会越界。游戏配置和技能卡配置是两个独立文件，可同时使用 `-game-config` 与 `-cards-config`。

坐标以格为单位，从 0 开始；x 表示列、y 表示行。左上与右下是格线交点，使用半开区间：`(0,0) → (1,1)` 占 1 格，`(2,3) → (6,7)` 占 4 列 × 4 行，共 16 格。右下是占用范围的边界，不是最后一格的索引。

`bidbrawl config` 查看宿主配置，`config -room ROOM_ID` 查看房间固定配置；`handbook -topic cards -live -room ROOM_ID` 展示实际尺寸、价格、资产规则和卡牌目录。默认配置位于 `internal/game/default.json`，编译进二进制；自定义 JSON 无需重新编译。当前游戏配置版本为 2、对局快照版本为 6、账号数据库版本为 3（账号内保存 `assets`）；只支持当前格式，不提供迁移或兼容分支。

## 完整行填充

1. 每局在 1～箱高之间等概率选取已使用行数 H，这个数在开局前对玩家隐藏。
2. 维护每列从顶部连续填满的格子数。从填充高度最低的列开始；并列时选最左列，因此每次都从最上、最左的未填格开始。
3. 向右找出填充高度相同的连续列数 S，并受物品最大列数限制。物品宽度在 1～S 中等概率选择，高度在 1～min(物品最大行数, H − 当前填充高度) 中等概率选择；二者独立抽取。
4. 放下这个矩形，更新它所占各列的填充高度，再重复，直到每列都填满 H 行。每件物品独立抽取品质与价格。

所有已使用行的每个格子恰好被一件物品覆盖，没有空洞、重叠、行尾空白或跨行缝隙。空白只能位于底部 `[0, 箱宽) × [H, 箱高)`；也可能恰好占满整个箱子。尺寸由逐件填充产生，物品数量随之随机；不设固定目标件数。窄箱、矮箱和最大尺寸为 1×1 都可处理。

物品数量每局重新生成，没有固定件数：填充行数随机，每件尺寸也随机，因此即使两局使用相同行数，件数也可能不同。随机结果可以重复，并不强制与上一局不同。数量受箱体容量和物品占格上限约束；例如物品只能占 1×1 格时，件数必然等于箱宽 × 已使用行数，但已使用行数仍逐局随机。截图中显示的数量只属于该局。

采用 Go 实现的逐件填充算法，每件物品独立选取可行的占格宽高；相邻物品的上下边界可错开，不再强制共享整条水平带。任何未填位置都至少能放 1×1 格，所以无需重试、丢弃物品或突破尺寸上限。已使用区域最终仍是完整矩形，而内部可以形成不规则的矩形拼接。窄箱、单行或占格上限为 1 时，会自然出现较规整的布局。

这里生成的是满足尺寸上限的物品，不是对一组预先给定的矩形求解装箱；没有引入 PackingSolver 或其他外部运行时。各件物品的尺寸分布受当前位置的可行空间约束，不代表对所有可能布局等概率抽样。

WebUI 直接使用格子坐标：默认 SVG 画布为 `0 0 20 30`，网格间隔为 1，每小格对应一个游戏格子，物品按占用列数和行数贴边绘制。屏幕缩放只改变显示大小，不改变格子数；观察规则的 `coordinate_unit: "cell"` 声明同一单位。未揭示的物品仍不会绘制，开箱前看到的空白不代表那里没有物品。布局、已使用行数与所有物品的位置在结算时完整公开。
