# 游戏与物品配置

物品模板可选 `translations`，按语言代码提供名称，例如 `"translations": {"en": "Cut-crystal decanter"}`。WebUI 图鉴按当前语言显示该字段；没有对应翻译时保留 `name`。内置物品的英文名同样存放于目录 JSON，不在界面代码中维护。

`-game-config` 加载尺寸、品质区间、权重、初始资金、门票与专长；默认配置见 internal/game/default.json，离线导出用 `bidbrawl config -defaults`。初始现金 600000，只影响新注册账号。五档价格为 80–320 / 300–1300 / 1000–5000 / 3000–15000 / 8000–50000，权重 45/30/15/8/2。

五档区间允许局部重叠：最高品质目标不必是最高价目标；同品质也会因具体身份和 value_percent 出现明显价差。尺寸与品质仍不强制正相关。扩大价格区间时保留史诗/传说区间中点，避免仅靠抬价加剧资金封顶；物品箱建议现金同步为 600000，已有账号现金不重置。

本次占格调整前目录的历史采样使用固定种子 20261018/1、每箱型 400 个生成样本（10 种箱型共 4000 箱，只统计常规物品，非 Agent 对战）：各箱型箱值中位数为 259265–322084，95 分位为 539038–588694；超过新号扣票后 595000 现金的比例为 2%–4.5%。最高常规品质贡献约 26.5%–28.3%。这些数值不代表调整占格后的当前分布，也不证明玩家策略已平衡。

物品目录独立存放于 internal/game/items.json，含 categories、warehouses、items。宿主 `-items-config PATH` 可替换物品模板列表（使用现有20个常规品类及彩蛋、五档常规品质和独立彩蛋档）；也可在 game-config 的 catalog 数组中配置模板。每档至少有一个常规 1×1 模板，确保任意剩余空间可填充。当前内置560个独立常规模板及8个彩蛋模板。字段为 id、name、category、quality、width、height、value_percent，可选 tags（如 clock）。后者是该档价格区间内 0–100 的位置，价格 = min_price + floor((max_price-min_price)×value_percent/100)。原始目录不使用市场价；实际价格由 catalog / state.rules.catalog 展示。无立绘依赖。

每件具体物品只有一个固定品质，名称以材料、用途、型号、工艺或来源区分，不给同一原型套五档通用品质前缀。品质是本游戏的价格档位，不是现实鉴定评级；附来源记录、签名或证书的名称属于游戏内设定。尺寸按收纳占格表达，卷轴、折叠件、成套物品按存放状态设计，不是实际长度比例。默认目录的每个常规“品质＋宽×高”组合至少对应两个独立模板，并在默认价格区间下保留至少两种价格，避免仅凭品质与尺寸唯一反推物品或价格。品类、标签等额外线索仍可能进一步缩小候选范围；此约束不保证所有信源组合都无法精确定价，也不要求每个品类的每种尺寸都有五档版本。各档模板数量不决定品质出现率，仍先按配置权重抽品质，再选可放入的物品。目录调整只作用于新建房间，已有房间继续使用冻结的目录与已生成物品。

公开目录中的 `quality_appearance_probability` 对常规品质按五档常规权重单独计算，排除彩蛋，五档之和为1（默认45%、30%、15%、8%、2%）；彩蛋档单独返回其基础抽取概率，不参与常规品质归一化。`appearance_probability` 是该件具体物品的基础单次抽取概率，仍计入彩蛋占用的抽取机会，保持与实际抽取机制一致。两者均由后端计算（0–1），不是数据文件中的手填概率；完整候选池、空间足够时，单件概率按该档可放入模板分配，主题品类计三份权重。物品无法放入配置箱体时单件概率为0。过滤查询不会重新归一化；房间查询、状态与复盘使用房间冻结配置和物品箱品类偏好。生成后续物品时，剩余空间会进一步筛选候选，因此该值不代表每个装箱位置的条件概率，也不代表整箱至少出现一次的概率。WebUI 仅把后端数值格式化为百分比。

生成时先选占用行数，按原 skyline 顺序找到可填位置，再按品质权重抽档、从可放入的该档模板中抽取。共有 10 种物品箱，建房时等概率抽选；综合物品箱无偏好，其余各偏好 2–3 个品类，覆盖全部 20 个常规品类。偏好品类在同品质候选池中权重三倍；其余品类仍可能出现。公开 warehouses 通过 favored_categories 数组提供偏好品类，网页规则与 CLI 使用同一份定义。固定模板决定形状与价值，不再先生成任意矩形再贴物品名称。所有占用行完整覆盖、底部可留空。目录和规则随房间快照保存，重启不会重抽。

账号 assets 表示现金。买卡扣现金、卡入库；用卡与库存扣除在房间事务中提交。成交扣报价并发放藏品，系统回收才增加现金。归档、删除对局不删除拥有的物品或重算余额。卡耗按实际购入成本计入本局净收益，未使用库存不算本局成本。配置变化不重置旧账号。

保留当前格式，不提供过时对局快照兼容。当前对局快照版本 10、账号数据库元数据版本 3。开发测试环境清理过时对局时保留账号及 DPAPI 凭据。

物品结构参考 [竞拍盒子](https://bidking.site/data/items) 和 [即刻落槌档案馆](https://ddangcalc.com/zh/items)：同形多候选、分类缩小范围、小物品也可很贵。首版名称与价格为本项目扩展后的平衡数据，不是原作数据的完整移植。

彩蛋 category=easter_egg，quality=easter_egg，1×1，fixed_price=17500000；与普通价格区间分离。抽取时普通品质权重乘1000，彩蛋权重为传说原权重，故彩蛋概率严格为传说概率的千分之一，模板数量不改变总概率。默认彩蛋整体概率为2/100002（约每50001件一次），8个模板平均分配后单件概率为1/400008。`game_config.qualities` 只配置五档常规权重；`rules.qualities`、`/api/config` 与完整 `catalog` 返回的 `qualities` 另含独立彩蛋档。初始抽检、卡牌、专长与公共线索均排除彩蛋；数量、面积和平均占格等侦察统计也不包含彩蛋。玩家在结算开箱后获知彩蛋，结算仍计入其完整价值；授权人类观察者的全箱视角保持完整。

内置专长为 `quick`（速察）、`survey`（巡察，默认）、`research`（深研）、`planner`（筹划）、`adaptive`（择机），定义在 `internal/game/specialties.json`，以 `style` 选择机制，随房间 `game_config.specialties` 冻结。选择专长不再接受定向品类。可在 game-config 中覆盖 specialties；玩家用 catalog 查询。已有房间保留原专长定义与已经取得的情报，不替换成新规则。

私人题单每轮开始时冻结，六种题型随机提供三种：稀有及以上、史诗及以上、面积至少4格、稀有及以上且面积至少4格、宽或高为1格、面积至多2格的样本占比。每份报告从常规物品中独立有放回抽样6次，仅给低档（不足三分之一）、中档（三分之一至不足三分之二）、高档（至少三分之二）。重复抽到同一件是正常结果；分档不是整箱比例。不返回逐件属性、位置、ID、价格、精确计数或均值。深研补充报告和筹划增强报告使用12次抽样；深研前6次与初报相同，后6次补充。

| 专长 | 行动与时机 |
|---|---|
| quick | 第1轮 take 两份不同题目的报告，或 reserve 先取一份、另一份第2轮 take 并扩展到12次抽样；保留报告使用原冻结样本，第3轮失效 |
| survey | 第1、2、3轮自动各得一份新样本报告 |
| research | 第1轮 start 选题取得初报；第2轮 commit 放弃即时报告，第3轮自动交付同题12抽样结论；第2轮 take 可改取新报告，未承诺者第3轮不再追加 |
| planner | 第1–3轮 take（5次抽样）、bank 或 boost；bank 放弃当轮报告，积攒1点筹备，上限2；boost 消耗较早轮次的1点筹备，为本轮下一张普通侦察卡追加12抽样报告，未使用则失效。原价、库存与每轮用卡限制照常，不得用于价格或身份鉴定 |
| adaptive | 第2、3轮 choose 从三道未回答的私人课题中选一道，随后只取得所选答案 |

`POST /api/specialty` 接收 round、action、topic、reason；CLI 为 `specialty -room ID -round N -action ACTION [-topic TOPIC] -reason REASON`。每轮本人报价前最多一次专长选择，未选择不自动积攒筹备。先读 `self.specialty_state.actions/questions`，需要选题的行动必须提交提供的 topic。选择、进度、资源和理由仅本人及独立授权观察者可见；公共版本、state、SSE 不因私人选择变化。专长行动不占用卡牌次数。

ticket_fee 默认为5000，建房 ticket_fee 可覆盖（CLI -ticket），0为免费。成功开局时房间状态和全部门票在同一事务中提交；不足或持久化失败不扣票。退出用 POST /api/withdraw，拒绝报0；退出不退款、不收额外罚金。

私有行动存于房间 activities：请求只记录白名单参数、结果摘要、状态、时间和理由，不存凭据或完整原始请求。服务器事件与CLI上报来源分开；手册离线且匿名时无法记录。公开 state/replay/SSE 不携带私有行动、计数或修订号，个人 self.activities 和独立观察接口按权限读取，复盘帧在后端裁剪未来行动。

专长不提供精确价格、价格总和、精确均价、抽样均价或物品身份。脚本型配置中的 `value`、`average.measure=price`、`reveal.fields` 的 `price` / `identity` 均被拒绝；不保留 `mode=average`。公开目录仍可交叉缩小候选；匿名抽样不等于数学上排除了全部组合定价渠道。

自定义脚本型专长可使用 `steps`，不能同时指定 style；已有房间的脚本也沿用该解释器。step.condition 可省略，或为 previous_unique_highest（上一轮唯一正最高价）、previous_below_highest（上一轮正报价严格低于最高价）。只读取前一轮公开 history；并列最高不触发这两个条件，第1轮禁止上一轮条件。内置五种风格不使用报价排名条件。提前成交或弃权后不再发后续情报，不因报0、超时或退出获利。


专长 steps 按轮次排列；all 仅用于 reveal，mode=presence 仅用于无分组 count。统计模式保留 effect 的品类、品质、面积和分区过滤，与专长范围取交集；不能因为切换为均值或存在性而扩大侦察范围。

五种风格的数量取舍：巡察稳定取得3份6抽样报告；深研最多2份报告，承诺后以覆盖面换同题12抽样；筹划即时报告仅5抽样，以精度换选题和筹备灵活度；择机保留第2、3轮的选题机会；速察追求早期信息或牺牲一份早期报告换第2轮更大样本。`quick.reserve_draws` 可配置6或12（内置12，省略为6），`planner.report_draws` 可配置5或6（内置5，省略为6）；均随房间冻结。
